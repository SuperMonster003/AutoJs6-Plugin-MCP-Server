# 16 KB page alignment

Builds apply `io.github.supermonster003.autojs6-native-alignment:1.8.0`. Every assembled application APK
is checked and reports are written to `app/build/reports/native-alignment/`.
Use `:app:verifyNativePageAlignment` to assemble and check both debug and release APKs.
The variant tasks `:app:verifyDebugNativePageAlignment` and
`:app:verifyReleaseNativePageAlignment` also assemble their APKs first, so none of
these entry points requires an APK from a previous build.

The published 1.8.0 verifier also registers finalizers for `assemble*UnitTest`
(in this build, `assembleDebugUnitTest`), although JVM unit tests do not produce APKs. The app
build disables only these unit-test verification tasks. APK verification remains
enabled with its original failure policy, including rejection of native libraries.
Revisit this compatibility configuration when upgrading the shared build plugin.

CI compiles the JVM test variant before the aggregate verifier builds the APKs.
To reproduce an IDE rebuild from clean outputs:

```powershell
.\gradlew.bat clean :app:assembleDebug :app:assembleDebugUnitTest :app:assembleDebugAndroidTest
```

To check the standalone verification entry point from clean outputs:

```powershell
.\gradlew.bat clean :app:verifyNativePageAlignment
```

This plugin rejects native libraries on every ABI (`expectNoNativeLibraries=true`).

Every native dependency or toolchain upgrade must pass the gate again. Static alignment
does not prove runtime behavior: test on a device reporting `getconf PAGE_SIZE = 16384`
with compatibility mode disabled. No `android:pageSizeCompat` override is permitted.

中文: APK 校验任务会先自动组装所需产物, 可直接从 clean 后执行, 无需提前准备 APK.
JVM 单元测试不产生 APK, 仅跳过构建插件 1.8.0 为其误注册的校验任务, 实际 APK 继续检查.
构建门禁检查全部应用 APK 并输出 JSON 报告. 原生依赖或工具链升级后必须重新校验,
且需在页大小为 16384 的设备上关闭兼容模式后执行运行时验证.
